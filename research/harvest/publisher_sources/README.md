# Original publisher podcast acquisition

This path acquires independently published public podcast RSS enclosures. It does not send requests to YouTube, mirror a denied video endpoint or infer that a podcast and indexed video are identical editions.

`pilot-plan.json` identifies two initial sources. `expanded-plan.json` freezes nineteen publisher/feed-identified episodes from the twenty-two Apple-linked original index rows, with two exclusions and one unmatched current feed item. The original index, catalog/feed responses, source hashes and exact episode GUID/title/date edges are documented in `../tool-research/PRIMARY-SOURCES.md` and its receipts. Rights remain publisher-owned unless separately established; raw audio is local-only.

```sh
python research/harvest/publisher_sources/verify_guards.py
python research/harvest/publisher_sources/verify_existing_replay.py
python research/harvest/publisher_sources/download.py \
  --plan research/harvest/publisher_sources/expanded-plan.json
```

The actual run uses two download threads inside an exclusive, nonblocking `/workspace/channels-et-raw/.collection-worker.lock`. The main harvest writer uses the same lock, so independent processes cannot each reserve the entire shared raw budget. All raw content under `/workspace/channels-et-raw` counts toward 20 GiB; 6 GiB free filesystem reserve and 256 MiB per file are checked before/during/after writing. TLS/CA/proxy configuration is inherited, HTTPS source/redirects are required, and expiring signed redirect query values are not exported.

Downloads use `.part` files. Resume requires a matching source URL and HTTP validator with a correct `206 Content-Range`; a full `200` response restarts this job's partial. Existing completed files require a matching prior source/URL/hash/size manifest, a valid measured audio stream and current expected size/duration checks. Reviewed RSS exceptions additionally require identical source metadata and an applied local amendment bound to the exact actual hash, size and duration. Reuse preserves the original warning, strict failure, amendment and acquisition timing/executed-code lineage; local replay timing and its code hash live separately in `reuse_verification`. Unknown or modified artifacts are not silently reclassified as source evidence.

Promotion requires a complete declared response body where supplied, nonzero bytes, a SHA-256 hash and valid ffprobe audio/duration. Known nonzero RSS enclosure size must match; duration must be within max(10 seconds, 1%) of RSS. A mismatch is quarantined as `validation_mismatch`, not counted complete. This can also reveal stale publisher metadata or dynamic advertisements; the software does not decide which explanation is true. Keep the partial and evidence for a source-specific review instead of silently relaxing a threshold.

Four specific complete HTTP responses were subsequently accepted after independent model-agent review and coordinator approval, with dated amendments and exact source hashes. Their original strict failures remain in the journal. These records have `status=completed` for the saved current response and an explicit `validation_outcome` warning; RSS disagreements and original/video-edition equivalence remain unresolved. The default thresholds did not change, and no retry supplied replacement bytes for those four. `apply_duration_review.py` and `apply_rss_metadata_reviews.py` implement only those named approvals, without network requests.

`publisher-summary.json` is an atomic cumulative snapshot. `planned_jobs` is fixed at nineteen for the expanded run, `run_status` is `running`, `completed` or `completed_with_failures`, `terminal` states whether the run ended, and `in_flight` lists active source IDs. Records retain source identity, source kind, stable enclosure URL, known expected quantities, observed content type, local-only raw path, actual byte hash/duration and verification state. Terminal record states are `completed`, `failed`, `blocked`, `quota_stopped` and `validation_mismatch`. `publisher-attempts.jsonl` retains attempts. No status named completed is inferred from a HEAD request or process launch.

The two initial targets were absent and streamed fresh. `code-versions/` and `execution-code-register.json` preserve the executed initial, expanded-run and Gateways-retry code. Later guards were added following independent review; one MIME diagnosis added support for `binary/octet-stream` and permitted a single targeted retry of the same original Gateways enclosure, under the unchanged nineteen-source plan hash. That retry passed exact RSS size, duration, hash and ffprobe checks. A subsequent replay-only correction preserves reviewed warning lineage on existing-file reuse and did not acquire any media. `guard-verification.json` records sixteen no-network adversarial/synthetic tests, with synthetic artifacts deleted rather than included in the corpus. `existing-replay-verification.json` records sixty passing read-only checks across all nineteen actual files, including preservation of all four warning records, original capture timing and executed-code pins; network access and raw/held-export writes were blocked during this check. Independent raw-artifact review lives in `../audits/`.

`delivery-redaction-receipt.json` records a security-only redaction of historical public metadata: CDN delivery paths can contain expiring authorization, so final endpoints and redirect chains expose origin only, a redacted-path flag and query key names. The stable original RSS enclosure is the source locator. Removed delivery values are not reproduced in the receipt, and audio bytes/hashes and original strict outcomes were unchanged.

Root's ASR workstream watches completed source records and writes `../asr/` metadata; full machine transcripts and raw recordings remain outside Git. Acquisition's frozen `transcript_status` is not an ASR progress counter. Join those separate ledgers by source ID and actual audio hash. Machine ASR is not human speaker, transcript or entity-origin validation. Publisher podcast counts, YouTube downloads, platform captions and machine transcripts remain separate metrics.
