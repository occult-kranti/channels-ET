# Bounded publisher-audio ASR queue

```sh
/workspace/channels-et-asr-venv/bin/python research/harvest/asr/run_queue.py --check-only
/workspace/channels-et-asr-venv/bin/python research/harvest/asr/run_queue.py --watch-seconds 1200
```

The default cohort is the nineteen-record `publisher_sources/expanded-plan.json`. No ASR launches until the publisher summary names that exact plan hash and planned count. Only actual completed, source-hashed audio can run. The dispatcher watches for at most twenty minutes, runs at most two processes with two CPU threads each, and honors the publisher `terminal` flag and explicit failure states. It is not a background service. A deadline or interruption terminates outstanding ASR processes and records that outcome; run the command again to continue remaining audio files. An interrupted file restarts decoding rather than resuming individual segments.

Existing transcripts are reused only after verifying source ID/URL/audio hash and size, full-audio scope, model revision/manifest, installed versions, decoding/thread settings, execution signature, retained executed source bytes, the exact three output hashes/sizes and public/private receipt agreement. A later entrypoint change does not invalidate a genuine older execution whose retained source proof still matches. The original two valid results therefore remain reusable. New entrypoint bytes are retained by hash before dispatch. A missing public bookkeeping mirror can be reconstructed from a completely verified private receipt; raw transcript text is never copied into the public summary.

`queue-state.json` separates attempted new processes, newly completed results, verified reuse, source failures and interrupted work. `queue-attempts.jsonl` records actual starts/finishes/reuse events. Failed ASR jobs from an earlier queue run require `--retry-failed` for another attempt; already verified results are always checked first. Raw child output goes only to `/workspace/channels-et-raw/asr-queue-logs/`, and completed text/SRT/segment files remain under the private raw transcript directory. `build_summary.py` refreshes public bookkeeping after processes finish. Neither queue completion nor automatic transcription establishes human-reviewed accuracy, speaker identity or equality to a YouTube edition.
